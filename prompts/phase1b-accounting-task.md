## Что сейчас не так (проверено на данных)

`tracker/summary.py::summarize_productivity`, подневная ветка (после
`if unit == "session": ... return`): для дня без ключа `<session_id>:<date>` код берёт
долю оценки сессии `session_hours * day_event_count / lifetime_event_count`
(`prorated_session_baseline=True`) и засчитывает день покрытым.

1. **Двойной счёт.** У сессии с частичной нарезкой одни дни дают свои оценки, другие —
   долю от оценки всей сессии, хотя дневные оценки покрывают ту же работу. Окно
   2026-09-04..2026-09-10: ~200 ч из ~985 — такие доли.
2. **Дрейф закрытых дней.** Знаменатель доли — события сессии за всю жизнь. Когда сессия
   продолжается, уже закрытый день задним числом теряет часы.
3. **Фальшивое покрытие.** День с долей считается «покрытым», хотя оценки этого дня нет.
   Замер 2026-09-11 по парам «сессия, день» с событиями: окно 7 дней — 62 пары, своя
   дневная оценка у 28 (785.2 ч), только доля — у 34, без ничего — 0; окно 30 дней —
   242 пары, своя оценка у 138 (2660.2 ч), только доля — у 96, без ничего — 8. Покрытие
   при этом показывается как все пары с долями.

## Что сделать

### 1. Числитель — только дневные оценки

- День засчитывается в числитель, только если у пары есть запись `<session_id>:<date>`
  с числовой оценкой (`effective_task_hours` не None).
- Путь с долей от оценки сессии удалить целиком. `read_lifetime_session_event_counts`
  оставить как функцию (диагностика), но в формуле не использовать.
- Ограничители `effective_session_hours` (подъём до активного времени, потолки) в этом
  заходе НЕ менять — иначе замер до/после смешает два эффекта.
- Путь `unit == "session"` не трогать.

### 2. Закрытые, открытые и неизвестные дни

- Открытый день — локальная текущая дата. Его пары не входят ни в числитель, ни в
  покрытие (оценка незакрытого дня не окончательна). Текущую дату бери через отдельную
  маленькую функцию, которую тесты могут подменить.
- Закрытые пары окна с событиями = допустимые единицы. Из них: оценённые (есть дневная
  оценка) и неизвестные (нет).
- Внимание (знаменатель) — только по оценённым закрытым единицам, как сейчас по покрытым.
- Новые поля результата: `units_eligible`, `units_estimated`, `units_unknown`,
  `units_open`, `window_complete` (истина, когда `units_eligible > 0` и
  `units_unknown == 0`). Для совместимости: `sessions_covered = units_estimated`,
  `sessions_total = units_eligible`.

### 3. Backend

`backend/server.py`:
- `productivity_payload` и `_productivity_block` пробрасывают новые поля.
- `_productivity_block` добавляет `multiplier_complete` = `window_complete` и множитель
  не заглушён (не floor, не меньше 1). Множитель при неполноте НЕ обнулять: скрывать его
  будет тема, а обнуление в backend сломает «за всё время», которое полным не бывает.
- `_today_productivity_block`: сегодняшний день открыт; поведение должно быть
  предсказуемым (без оценок — пустой блок с `units_open`), без исключений.
