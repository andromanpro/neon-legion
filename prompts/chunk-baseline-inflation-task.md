## Дефект (воспроизведён на живых данных 2026-09-03)

В `tracker/summary.py::summarize_productivity`, ветка chunk-режима, есть падение назад
на сессионную оценку:

```python
if not present_chunk_keys:
    total_units += 1
    if session_hours is None:
        continue
    record_unit(session_hours, ...)   # <- ВЕСЬ baseline сессии
```

`present_chunk_keys` строится только из тех дней, что попали в окно расчёта. Поэтому в
окне «один день» у любой сессии, у которой нет ключа `<session_id>:<этот день>`,
засчитывается её ПОЛНЫЙ baseline за всю жизнь.

## Что сделать

### 1. Пропорциональное распределение вместо полного baseline

Когда для дня внутри окна нет подённого ключа, а сессионная оценка есть — засчитывать
не весь baseline, а долю этого дня. Долю считать по активности сессии: доля дня =
события сессии за этот день, делённые на все события сессии за всю её жизнь (не только
за окно — иначе однодневное окно снова даст долю 1.0). Если данных о событиях за
пределами окна нет, используй наиболее консервативную доступную оценку и явно
опиши выбор в отчёте.

**Инвариант, который обязан держаться:** сумма зачтённых часов сессии по всем
календарным дням её жизни не превышает её baseline. Ни один день не может получить
больше, чем сессия сделала за всю жизнь.

Реализацию выбираешь сам, но она должна быть одна и та же для всех режимов окна
(1 день / 7 / 30 / всё время), без частных случаев «если окно короткое».

### 2. Отчёт backfill-скрипта не должен врать

`tracker/backfill-codex-estimates.py` (и `backfill-stranded-estimates.py`) печатают
`✓ N ч`, проверяя только появление `ai_baseline_hours`. Но `estimate_session` сначала
пишет сессионную оценку, а ПОТОМ нарезает подённые чанки отдельными вызовами оракула.
При таймауте процесс убивают на середине нарезки — оценка есть, чанков нет, а скрипт
рапортует успех. Именно так сессия 019f8053 получила 160 часов и чанки только за
20–29 июля.

Сделай так, чтобы отчёт различал «оценена и нарезана» и «оценена, нарезка не
завершена». Формат вывода на твоё усмотрение, но неполный результат обязан быть
видимым в консоли.

### 3. Тесты

Новый файл `tests/test_chunk_baseline_proration.py`. Обязательные случаи:

- сессия живёт N дней, окно = один из них → засчитана доля, а не весь baseline;
- сумма по всем дням жизни сессии не превышает baseline (тот самый инвариант);
- сессия с полной подённой разбивкой считается ровно как раньше (регресс);
- сессия целиком внутри окна даёт свой полный baseline;
- день, в который у сессии нет событий, не получает ничего.

Негативный контроль обязателен: тест, который падает на СТАРОМ поведении. Проверь это
явно — временно верни старую логику, убедись, что новый тест краснеет, верни новую.
Факт проверки укажи в отчёте.
