## Дефект 1 — дневные оценки Codex сделаны по пустому тексту (проверено)

`tracker/estimate-task.py`:
- `read_transcript` (стр. 365) для кодексовых транскриптов делегирует в
  `codex_transcript.read_messages` (стр. 370–371) — оценка сессии целиком видит текст.
- `estimate_session` (стр. 668–~830) режет транскрипт по дням своим циклом; сборка
  дневных сообщений (около стр. 751–778) идёт через `transcript_role` (стр. 229) и
  `transcript_text` (стр. 243) — это claude-функции, они не видят кодексовый формат
  `{"type":"response_item","payload":{"type":"message","role":...,"content":[...]}}`.

Факт на живых данных: сессия `019f8053` (Codex), 8 дневных оценок — claude-путём
0 сообщений на каждый день, кодексовым адаптером 89–500. Всего так оценены 56 дней Codex
на 669.6 ч: оракул получил пустую переписку и масштабировал часы по метрикам.

Нужно: дневная сборка обязана использовать тот же разбор, что и `read_transcript`, для
обоих форматов (фильтр инжекта Codex — `codex_transcript.is_injected` — тоже). Одна
функция классификации/извлечения сообщения на событие, общая для оценки сессии и дней.

## Дефект 2 — пересказ после сжатия считается промптом человека (проверено)

Claude Code при сжатии пишет в транскрипт:
- запись `{"type":"system","subtype":"compact_boundary",...}`;
- пользовательское сообщение-пересказ `{"type":"user","isCompactSummary":true,
  "isVisibleInTranscriptOnly":true,"message":{"role":"user","content":"This session is
  being continued from a previous conversation..."}}`.

`tracker/summary.py::is_human_prompt` (стр. 851) пропускает такой пересказ: в сессии
`43b70eba` 14 из 14 пересказов засчитаны как промпты (всего по данным 77 пересказов в
36 сессиях). Следствия: (а) лишние метки в знаменателе внимания
(`read_human_message_timestamps`, стр. 887; `_human_attention_hours_for_units`, стр. 980);
(б) пересказ попадает во вход оракула — `build_truncated_context_from_messages`
(стр. 463) берёт первые 3 реплики человека, и пересказ прошлых недель оказывается
первой «задачей дня».

Нужно: синтетический пересказ (`isCompactSummary: true`) не является промптом человека
и не входит во вход оракула — ни для оценки сессии, ни для дня. Один предикат, общий для
`summary.py` и `estimate-task.py` (estimate-task намеренно не импортирует summary —
общий код клади в лёгкий stdlib-модуль в tracker/, как уже сделано с codex_transcript).
Для Codex убедись тестом, что записи `type=compacted` (история лежит в
`payload.replacement_history`) не превращаются ни в промпты, ни во вход оракула.

Не ломать: настоящий промпт человека рядом с `tool_result`, промпт со строковым
`content`, фильтр сайдчейнов (`isSidechain`) и существующее поведение `is_human_prompt`
для обычных сообщений.
